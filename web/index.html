两种生成模式

顶部有两个标签页，区别只在「怎么理解你那句话」，生成 XML 的代码是同一套。

模式怎么工作前提速度
自然语言生成 大模型只输出一个极小的 JSON（选哪个模板 + 几个参数 + 置信度），XML 由确定性代码生成 需要 API Key（在「设置」里粘贴） 1～4 秒
仅用模板（不联网） 本地关键词打分，直接命中模板 不需要 Key 毫秒级
两种模式产出的文件逐字节一致 —— 模型从不写 XML，所以不存在「生成的 XML 语法错」这种问题。

为什么不让模型直接写 XML

模型的自由度放在「理解意图」上，语法层面的正确性由代码保证。这是本项目最核心的设计取舍。

按金额 / 天数自动分级

一句话里说出阈值，就会生成对应的排他网关和分支，阈值从话里抽出来。

差旅报销，金额小于1000主管批，超过5000需要财务复核

会生成三条分支：

条件去向
amount <= 1000主管审批
amount > 1000 && amount <= 5000总监审批
其余（默认流）财务复核

天数也能分级

请假3天以内主管批，超过7天人事批
阈值支持阿拉伯数字、单位「万/千」，也支持中文数字：五千=5000、两万=20000、一万五=15000。如果数值没认出来，或者你说的档位比模板能放的多，生成结果下方会出现黄色提示条，写明用了什么代替 —— 不会悄悄替换。

审批驳回 / 退回

凡是有审批节点的流程，都自带驳回能力：审批人点「不通过」，单子退回发起人重新走。

技术上是怎么做的

用 BPMN 的回边实现，不是画个圈糊弄：

  • 「通过」= 默认流（default flow），条件全不满足时走它；
  • 「驳回」= 带条件 execution.getVariable('approved') == false 的流，指回发起节点。
驳回后流程不会自己结束，而是回到前面重走 —— 这正是真实审批的行为。图上那条向左的箭头就是驳回路径。

看效果

生成流程后点「下载说明」，文档里有一节「驳回 / 退回路径」，会列出每条回边的来源、去向和条件。

是 / 否 业务分支

很多审批不是按金额分级，而是一个「是／否」判断决定要不要多走一道工序。28 个模板里都内置了这种分支，判断条件由发起人在表单里勾选。

场景判断条件肯定时多走一道
用章申请是否外带用印法务审核
离职审批是否涉密岗位安全审查
IT 权限申请是否生产环境运维总监审批
出差申请是否出境行政审核
公文签发是否急件主要领导签发
用车申请是否出市行政经理审批

怎么用

直接描述场景即可，例如「我要用章盖章」。生成后图上会出现一个菱形判断节点，两条出口分别写「需要外带」和「现场用印」。

申请系统权限
这些「是／否」变量会自动出现在「下载表单」的字段里（type=boolean），前端照着渲染成勾选框即可，不需要另外约定。

会签（全部签完） / 或签（一人即可）

用 BPMN 的多实例任务实现，人数不写死在流程里。

多人会签，全部签完才通过
或签，任意一人处理即可
类型BPMN 写法行为
会签多实例，无完成条件approvers 里有几个人就签几次，全签完才继续
或签多实例 + nrOfCompletedInstances >= 1任意一人签完，整个任务立即通过
人数由流程变量 approvers 列表长度决定：传 3 个人是三人会签，传 5 个是五人。业务上换人增人只改数据，不用重新建模。

超时催办 / 自动升级

给审批任务挂一个边界定时器：到点还没处理，自动转到升级分支。

审批超时3天没处理就自动升级

生成的结果里，主管审批节点的右下角会多一个小圆圈（边界事件），超时后走到「上级审批」。

你说定时器
3 天没处理P3D
8 小时PT8H
超时后原任务会被取消（cancelActivity=true），避免两个人同时处理同一张单子。

拿不准就先问，不硬生成

两种情况下应用不会直接出图，而是把候选模板摆出来让你点：

  • 关键词得分太低（低于 4 分），或与第二名差距不足 2 分；
  • 大模型返回的置信度低于 0.7。

候选卡片会显示「识别到：」命中了哪些关键词，帮你判断它为什么这么猜。点一下即生成。

命令行版没有交互上下文，所以会打印候选清单，再用 --template 模板id 重跑一次。

除了 XML，还产出三样东西

产物内容给谁看
流程说明书（Markdown）节点表、分支条件表、驳回路径、校验声明评审 / 交接 / 存档
表单定义（JSON）发起人要填的字段、类型、是否必填前端页面开发
分支覆盖用例（JSON）每个分支一组输入样例 + 预期去向测试同学

界面上对应「下载说明」「下载表单」两个按钮；命令行加 --artifacts 会一次落三个文件。

用例里的样例值是算出来的：上界条件取「阈值 − 1」，区间取「下界 + 1」，默认流取「最大阈值 + 1」。所以拿来就能跑。

模板库怎么用

左侧「模板库」列出全部模板，含编号、名称、适用场景、关键词。想稳定命中某个模板，句子用它的关键词即可。

模板是纯 JSON，可以自己加

一个模板就是一个文件，放在 src/templates/，包含：节点、连线、变量、关键词、槽位。加完重启应用即可出现在模板库里，不需要改任何代码。

模板里的槽位写成 @tier1@ 这种占位符，生成时替换成从你话里抽出来的数字。

命令行版（同功能）

界面和命令行共用同一套内核，产物逐字节一致。

命令作用
nl2bpmn.cmd --list列出全部模板
nl2bpmn.cmd "差旅报销..." -o out.bpmn生成并输出
nl2bpmn.cmd "..." -o out.bpmn --artifacts同时产出说明 / 表单 / 用例
nl2bpmn.cmd "..." --template amount_tiered指定模板，跳过关键词猜测
bpmn2svg.cmd out.bpmn把 BPMN 渲染成 SVG
verify-all.cmd跑完整六层验证

常见问题

它说「把握不大」，让我选模板？

说明你这句话和模板的关键词重合度不够。点候选里的任意一个即可；或者把句子改成模板描述里的说法。

生成的分支和我说的话不一致？

先看生成结果下方的黄色提示——阈值没识别出来、分支数超过模板能力，都会在那里说明，不会悄悄替换。

能直接部署到引擎吗？

目前产出标准 BPMN 2.0 文件，导入 Flowable / Camunda 即可部署；应用本身不直连引擎。

生成的文件能过校验吗？

每个模板都要通过六层验证：良构 → IR 契约 → 图论 → OMG 官方 XSD → bpmn-moddle → Flowable 引擎实跑。
