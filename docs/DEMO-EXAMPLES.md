# 演示示例清单（带 Key 版本）

> 每句都经过模板匹配验证，预期结果有据可依。
> 实际运行时**置信度和模型理由每次略有不同**，但模板与结构稳定。

## 一、主推三个（视频里用这三个就够）

### 示例 1｜金额分级（最能体现"理解语义"）

**输入**：
```
我要做一个差旅报销审批流，金额小于1000直接主管批，大于1000需要总监批，超过5000需要财务复核
```

| 项 | 预期 |
|---|---|
| 模板 | `amount_tiered`（金额分级审批） |
| 结构 | **7 节点 / 8 连线** |
| 提取 | `tier1=1000`、`tier2=5000` |
| 耗时 | 2~5 秒 |
| 图的样子 | 开始 → 提交 → **金额判断网关** → 三条并行分支（主管/总监/财务）→ 结束 |

**口播**：
> 我输入这句话——三个金额区间、三个审批人。点生成。
> 它会先让模型判断这是"金额分级"场景，抽出两个阈值，再生成流程。
> 出来了：一个排他网关分出三条路，主管、总监、财务，最后汇到结束。

**看点**：把鼠标依次划过三条分支，停 2 秒。

---

### 示例 2｜并行会签（结构完全不同，证明不是套模板）

**输入**：
```
采购合同需要法务、财务一起会签
```

| 项 | 预期 |
|---|---|
| 模板 | `contract_review`（合同并行会签） |
| 结构 | **8 节点 / 9 连线** |
| 图的样子 | 提交 → **并行网关分叉** → 法务/财务/业务三方 → **汇合网关** → 结束 |

**口播**：
> 再换一个完全不同的结构。这次是三方会签，需要同时审。
> 系统识别后用了**并行网关**——三条线同时走，全部完成后才汇总。
> 注意这不是把上一个模板改一改，是换了另一种流程结构。

**看点**：指一下分叉和汇合两个网关。

---

### 示例 3｜请假天数（最贴近日常）

**输入**：
```
请假3天以内主管审批，超过3天需要人事备案
```

| 项 | 预期 |
|---|---|
| 模板 | `leave_days` |
| 结构 | **6 节点 / 6 连线** |
| 提取 | `tier1=3` |
| 图的样子 | 填写请假单 → **天数判断** → 主管审批 / 人事备案 → 结束 |

**口播**：
> 日常审批也一样。三天以内主管批，超过三天走人事。
> 这里只提了一个阈值——三天，它只填一个参数，另一个保持默认。

**看点**：说明"短描述也能用"。

## 三、反例（强烈建议加，15 秒，加分项）

**输入**：
```
帮我订一张去上海的机票
```

| 项 | 预期 |
|---|---|
| 结果 | **明确拒绝**：没有匹配到任何模板 |

**口播**：
> 那如果输入的不是审批流呢？比如"帮我订一张机票"。
> 它会明确告诉你——这不是流程配置需求，而不是硬凑一个流程出来。
> 我宁愿它拒绝，也不要它生成一个看起来像、但实际上跑不通的东西。

**为什么这个是加分项**：说明系统有**边界意识**，不是"什么都能生成"的自欺欺人。

## 四、现场应变

| 情况 | 怎么办 |
|---|---|
| 模型选了别的模板 | 不要慌，顺势讲："模型判断这是 X 场景"——评委看到的是**模型的判断**，这不丢分 |
| 置信度偏低（<0.7） | 可以说："这次它不太确定，但仍然给出了合理结构" |
| 生成超过 8 秒 | "网络稍慢，在等模型返回"，继续等，**不要中断** |
| 报错/失败 | "模型偶尔会返回不合规结果，系统会直接拒绝而不是硬凑"，然后重试一次；再失败就切离线模式 |
| 界面突然显示"无密钥" | 黑窗口被关了，Key 没了——先停机，重新录入再录 |
